# РАКОВАРЪ — интернет-магазин

Flask, PostgreSQL / SQLite и vanilla JS. Заказы с оплатой при получении оформляются на сайте через `/api/store/orders`: сервер рассчитывает цены, скидки, доставку и бонусы, резервирует учтённый склад и сохраняет контакты в зашифрованном виде. Онлайн-эквайринг не подключён. `DATABASE_URL` включает PostgreSQL с семью последовательными миграциями; SQLite предназначен для локальной проверки.

Описание текущей поставки и её ограничений: [магазин и эксплуатация](docs/STORE_OPERATIONS_2026-11-11.md). Документы P0 описывают предыдущий демонстрационный API, который сохранён для совместимости.

## Покупатель

- 59 позиций с опубликованными ценами и фотографиями; категории, поиск, сортировка, избранное и постраничная загрузка.
- Пять размеров живых раков: Mini, Standart, Maxi, Mega, XXL. Количество в килограммах с шагом 0,5 кг по умолчанию.
- Конструктор из всего опубликованного меню: поиск, количество, готовые составы, подбор под бюджет и число гостей, сохранение своих наборов на устройстве.
- Корзина с серверным расчётом, промокодами, подарками клуба, бонусами, доставкой и самовывозом.
- Кабинет `/account`: собственные заказы, история статусов, повтор заказа, профиль, избранное, сохранённые наборы, бонусный счёт и уведомления. Регистрация и вход по email и паролю; подтверждение email и самостоятельное восстановление пароля ещё не реализованы.
- Возврат 5% бонусами после подтверждения оплаты; списание до 20% стоимости блюд. Оба значения настраиваются. Тестовые игровые баллы не становятся деньгами в корзине.

## Управление

Ссылка на служебный вход отсутствует на витрине и в кабинете. В конфигурации публичного выпуска `HIDE_STAFF_ENTRY=true`: анонимные `/admin` и `/admin/login` отвечают 404. Отдельный вход сотрудников — `/team/rakovar-control/login`; доступ к данным защищён паролем, серверными ролями и отзываемыми сессиями. Скрытый адрес сам по себе не является механизмом авторизации.

Админка управляет каталогом, фото, черновиками, ценами, складом и историей корректировок, заказами и статусами, профилями покупателей, бонусами, доставкой, акциями, призовым фондом и интеграциями. Фотографии можно выбирать из медиатеки или загружать в постоянную БД. Изменения операторов сохраняются при обновлении исходного каталога.

Внутренние уведомления о заказах сохраняются в БД. Отправка обезличенных уведомлений в MAX / Telegram требует ключей и адресата, а также включения нужного канала в настройках магазина. Подключения VK / MAX / Telegram имеют зашифрованные настройки, проверку доступа, журнал отправок и ручную обработку неоднозначного результата. Сохранение ключа не публикует сообщение. Проверка реальной доставки возможна только после настройки владельцем.

## Каталог и источники

Исходный каталог содержит 74 карточки. 15 неполных карточек остаются черновиками без кнопки покупки. Пицца и прежние ошибочные позиции отключены. Для новой медиатеки сохранены 28 проверенных фотографий публичной карточки компании; соответствие конкретному блюду фиксируется отдельно, фото похожего блюда не считается точным совпадением.

Цены импортированы из опубликованного меню и **не подтверждены компанией на дату запуска**. Остатки по умолчанию не считаются фактическими: на витрине указано «Под заказ», пока сотрудник не включит складской учёт и не внесёт остаток. `stock=99` в исходных данных — технический предел прежнего preview.

Предоставленный `rakovar76.clients.site` во время проверки показывал `SiteUnavailable`. Не удалось гарантированно получить всё меню с этого адреса. Доказательства переноса и происхождение фотографий: [источники](docs/research/store-source-2026-11-11.json), [медиа](docs/research/store-assets-2026-11-11.json), [каталог на согласование](docs/research/catalog-for-approval.csv).

## Локальный запуск

1. Скопируйте `.env.example` в `.env`, задайте стабильные случайные `FLASK_SECRET_KEY` и `INTEGRATION_ENCRYPTION_KEY`, хеш `ADMIN_PASSWORD_HASH`. Не добавляйте `.env` в Git.
2. Установите зависимости: `pip install -r requirements.txt`.
3. Выполните `python prepare_render.py`, затем `python app.py` или `gunicorn app:app --bind 0.0.0.0:8080`.
4. Для локальной проверки используйте SQLite. Для постоянных данных задайте `DATABASE_URL` PostgreSQL. Миграции применяются при старте.

Постоянный ключ шифрования обязателен для чтения ранее сохранённых контактов и ключей интеграций. Его смена без переноса данных приведёт к потере доступа к этим данным. Пароли задаются приватно; исходники не содержат рабочих кодов входа.

## Проверки

```bash
pip install -r requirements-dev.txt
python scripts/validate_preview.py
pytest -q
node --check static/storefront.js
node --check static/studio.js
node --check static/account.js
node --check static/admin.js
node --check static/shop-admin.js
```

`pytest` дополнительно запускается с временным PostgreSQL. `scripts/browser_check.py` использует только одноразовую локальную БД, синтетические контакты и пароли: проверяет витрину, скрытый вход, корзину, повтор запроса после потери ответа, заказы, склад, акции, роли, MFA и мобильные состояния. GitHub Actions выполняет все три группы проверок.

## Render

`render-store.yaml` обновляет существующий бесплатный сервис и связывает его с уже созданным PostgreSQL. Постоянная БД публичного preview — бесплатная и имеет срок действия до 10 декабря 2026 года; для дальнейшей эксплуатации нужен согласованный постоянный тариф и резервное копирование. Не создавайте платные ресурсы без согласования.

`prepare_render.py` проверяет исходники и ресурсы, не извлекает старый архив и не перезаписывает UI. `DEMO_MODE=true` сохраняет прежний демонстрационный игровой контур и `/api/orders`, который отбрасывает контакты; новый `/api/store/orders` хранит реальные заявки отдельно с шифрованием. Не используйте старый API для коммерческого checkout.

Перед коммерческой эксплуатацией владелец должен подтвердить цены, наличие, тарифы, реквизиты, правила лояльности и обработки данных. Онлайн-оплата, email-подтверждение / восстановление, автоматические резервные копии и приёмка реальных внешних интеграций остаются отдельными задачами.
