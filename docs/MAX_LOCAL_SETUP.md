# MAX: локальный предпросмотр без постоянного хостинга

## Что уже подготовлено

- `max_client.py` — HTTPS-клиент для `platform-api2.max.ru`; токен берётся только из `MAX_BOT_TOKEN`.
- `max_bot.py` — Long Polling для локальной разработки: `/start`, `/catalog`, `/club`, `/tickets`, `/id`, `/help`; при старте бот регистрирует эти команды через `PATCH /me/commands`.
- `/api/max/auth` — серверная проверка подписи `window.WebApp.initData` по алгоритму MAX WebAppData; проверяется срок `auth_date` (1 час).
- Бот может отправлять владельцу обезличенное уведомление о тестовой заявке, если задан `MAX_ADMIN_USER_ID`.

## Важно про токен

На скриншоте MAX токен замаскирован; извлечь действующее значение из изображения нельзя. Не вставляйте токен в исходный код и не отправляйте его в чат. Скопируйте его в локальный `.env` в `MAX_BOT_TOKEN`. Файл `.env` исключён из Git.

## Локальный запуск на Windows

1. Распакуйте проект в отдельную папку.
2. Скопируйте `.env.example` в `.env`.
3. Заполните `MAX_BOT_TOKEN`. Оставьте `MAX_MINIAPP_URL` пустым до создания HTTPS-туннеля.
4. Сгенерируйте хеш пароля админки: `python -c "from werkzeug.security import generate_password_hash; print(generate_password_hash(input('Admin password: ')))"` и вставьте результат в `ADMIN_PASSWORD_HASH`.
5. Сгенерируйте `FLASK_SECRET_KEY` командой `python -c "import secrets; print(secrets.token_urlsafe(48))"` и вставьте случайное значение. Для локального HTTP оставьте `COOKIE_SECURE=false`.
6. Запустите `run_local.ps1`. Откроются два отдельных окна: веб-сервер и бот. При старте бот проверит токен через `GET /me` и зарегистрирует команды через `PATCH /me/commands`.
7. Напишите боту `/start`, затем проверьте `/catalog`, `/club`, `/id`. В окне бота должен появиться статус `MAX bot connected`.

## Открыть Mini App в MAX временно

MAX требует публичный HTTPS URL. Постоянный домен и постоянный хостинг не нужны: используйте временный Cloudflare Quick Tunnel. В третьем PowerShell окне выполните:

```powershell
cloudflared tunnel --url http://127.0.0.1:8080
```

Скопируйте выданный адрес `https://….trycloudflare.com`. В MAX для бизнеса → Чат-боты → ваш бот → ⋮ → Настройки → Мини-приложение вставьте этот HTTPS URL, выберите кнопку «Открыть», сохраните. MAX требует HTTPS; ссылка должна быть доступна извне. Тот же адрес укажите в `.env` как `MAX_MINIAPP_URL`. После изменения `.env` перезапустите оба процесса. Официальная инструкция MAX: https://dev.max.ru/docs/webapps/introduction

Quick Tunnel временный: hostname случайный и меняется при каждом запуске; без Cloudflare-аккаунта и домена. Любой, у кого есть ссылка, сможет открыть демонстрационную витрину, поэтому не добавляйте реальные клиентские данные и не включайте платежи. Админка защищена отдельным паролем. Пока компьютер, Flask и `cloudflared` запущены, Mini App доступно по HTTPS; после остановки процессов ссылка перестанет работать. У Quick Tunnels нет SLA и есть лимит 200 одновременных запросов — только для теста. Официальная инструкция: https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/do-more-with-tunnels/trycloudflare/

## Ограничения MAX API

`max_bot.py` использует Long Polling только для локальной разработки. Официальная документация MAX указывает, что Long Polling не подходит для production; для постоянной работы нужен Webhook: https://dev.max.ru/docs-api/methods/GET/updates. MAX Mini App работает только внутри чат-бота и требует публичный HTTPS URL: https://dev.max.ru/docs/webapps/introduction. Если на боте уже зарегистрирована Webhook-подписка, Long Polling может не работать — сначала проверьте и удалите/отключите webhook-подписку или используйте отдельный webhook-процесс.

MAX API требует заголовок `Authorization: <token>` и домен `platform-api2.max.ru`. Команды бота регистрируются автоматически при запуске через `PATCH /me/commands`. Документация также требует добавить сертификат Минцифры в доверенные. TLS-проверка в проекте не отключается; если системного доверия недостаточно, укажите путь к официальному CA bundle в `MAX_CA_BUNDLE`.

## Заказные уведомления

Чтобы получать уведомления о тестовых заявках, напишите боту `/id`, затем установите полученный числовой ID в `MAX_ADMIN_USER_ID`. Команда также покажет клубный ID вида `max_123456` — его можно использовать для ручного начисления билетов в админке. Бот должен иметь возможность писать вам после того, как вы начали с ним диалог. Уведомление не содержит телефон, имя или адрес: в preview эти данные намеренно не сохраняются.

## Проверка подлинности пользователя Mini App

Клиент отправляет `window.WebApp.initData` на `/api/max/auth`. Backend проверяет HMAC-SHA256 по официальному алгоритму MAX, извлекает user ID и привязывает клубный баланс к `max_<user_id>`. `initDataUnsafe` не используется для авторизации.
