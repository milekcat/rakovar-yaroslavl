## 2. Основные публичные темы и работа с качеством сервиса

По публичным отзывам, связанным с конкретной ярославской карточкой, положительно упоминаются раки, свежесть и ассортимент, букетные композиции, оформление подарков и скорость части доставок. Есть и критические комментарии о **времени доставки** и **качестве приготовления отдельных блюд**. Для внутренней работы выделить категории: `product_freshness`, `taste_cooking`, `delivery_timing`, `support`, `packaging`, `pricing`, `gift_experience`.

Публичная витрина **не должна состоять только из пятизвёздочных сообщений** и вводить в заблуждение относительно общей оценки. Модерация внутреннего канала защищает от спама/оскорблений/ПДн, но не удаляет добросовестную критику ради маркетинга. Отзывы внешней площадки в её интерфейсе модерирует сама площадка; на нашем сайте показываем ссылки/разрешённые выдержки, а не притворяемся владельцем оригинала.

## 3. UX / навигация

### 3.1 Главная
Блок «Нам доверяют покупатели» после основного каталога/лучших товаров, перед историей/контактами. 2–3 независимых карточки источников с логотипом/названием, ссылкой «Читать на Яндекс Картах» / «Читать на Chibbis», датой обновления и точным provider-place-ID. Ни одного вымышленного «среднего рейтинга по интернету». Карусель выбранных **подтверждённых и разрешённых к публикации** отзывов с текстовым fallback и управляемой паузой, допускается ручная кураторская подборка с пометкой «Избранные отзывы».

Блок «Мы в социальных сетях»: VK и только подтверждённые фирменные аккаунты MAX/Telegram/других платформ; 3–6 последних разрешённых публикаций / обложки, дата, тематика, переход к оригинальному посту, кнопка «Подписаться» или «Написать». При ошибке API или неразрешённом iframe отображается статичная ссылка, не пустой сломанный виджет.

### 3.2 Страница `/reviews`
- Intro: почему нужны отзывы, актуальные источники и дата последнего обновления.
- Переключение `Отзывы на сайте`, `Яндекс Карты`, `Chibbis`; дополнительные вкладки только после подтверждения источников. Перейти к оригиналу можно всегда.
- Фильтры внутреннего канала по оценке, дате и тематике; сортировка свежие/полезные; поиск по тексту с защитой от PII.
- Review card: display_name (обрезать/псевдоним при согласии), дата, звёзды, заказ на сайте («подтверждённая покупка» только при реальной связи с завершённым заказом), текст, разрешённые фото, официальный ответ магазина, исходная платформа.
- Форма для клиента с заказом: оценка 1–5, категория, текст, до N фото, согласие на публикацию, опциональное разрешение на использование фото. Не публиковать номер заказа, email/телефон, адрес, историю платежей или иной PII.
- Сценарий негативного отзыва: безопасное приглашение в чат заказа/поддержку; не удалять публичную оценку автоматически при открытии обращения. Публичный ответ компании отдельно от внутренней карточки претензии.
- Раздел «Отзывы на других площадках» с объяснением внешних источников, без автоматического агрегирования.
- SEO: человекочитаемые метаданные и каноническая страница, не добавлять недопустимый `Review`/`AggregateRating` для self-serving LocalBusiness; проверять актуальные правила Google перед реализацией.

### 3.3 Страница `/community` или секция `/about#community`
Два обоснованных варианта: объединённая страница `/reviews` «Отзывы и сообщество» с вкладкой «Соцсети» либо самостоятельная `/community` при наличии достаточного количества подтверждённого контента. Рекомендация для первого релиза: **единая `/reviews`** (клиенту проще найти), компоненты «Мы в соцсетях» повторно используются в `/about`, `/contacts` и footer. Не плодить пустые SEO-страницы.

### 3.4 Кабинет покупателя
После действительно закрытого заказа предлагается оставить отзыв; один verified review per eligible order, версия/редактирование с историей, возможность отозвать согласие на публикацию своих фото и скрыть имя. Рейтинг товара и рейтинг общего сервиса **отдельно**; не выводить рейтинг бизнеса из оценок отдельных блюд.

### 3.5 Мобильный
Оценки читаются без горизонтального скролла 320px, крупные ссылки на оригинальные площадки, модальное увеличение фото с keyboard focus, skeleton/loading/error, сохранение фильтров; внешняя ссылка открывается безопасно с видимым текстом, не мешает оформлению заказа.

## 4. Административная панель: «Отзывы и репутация»

Отдельный раздел `/team/.../reviews` (точный путь выбирается после проверки текущего роутинга) с очередью новых внутренних отзывов, ответами, правами, публичным предпросмотром, жалобами, темами, историей действий и внешними ссылками.

Роли:
- `owner`/`store_manager`: полное управление процессом в допустимых границах, отчёты, политики ответов.
- `support`: просмотр разрешённых отзывов, ответы по назначенным обращениям, перевод проблемы в тикет заказа.
- `social_media_editor`: подготовка публичных ответов и подборок, но без доступа к балансу/PII/финансам, и без права скрывать добросовестный негатив без обоснования.
- `content_editor`: размещение разрешённых цитат в CMS с соблюдением provenance/consent.
- `finance`/`courier`: отзывные права по отдельным объектным разрешениям, по умолчанию без доступа к данным клиентов.

Модель источников: `review_sources(provider, source_business_id, url, active, verified, permission_mode)`, `source_rating_observations(provider_id, score, scale, count_ratings, count_reviews, observed_at, method, observation_url)`, `customer_reviews(id, customer_id, order_id, product_id?, rating, text, published_at, state, privacy_consent_version)`, `review_media`, `review_replies`, `review_moderation_log`, `community_channels`, `community_posts`, `support_cases`. Агрегатор рейтингов в версии 1 **не нужен**.

Фильтровать запрещённый/спамный контент по документированным правилам с reason, actor, timestamp, appeal; удаление персональных данных и обработка запросов субъекта по 152-ФЗ. Хранение и публикация фото людей/отзывов — отдельное право/согласие, по обстоятельствам применимые требования о правах на изображение.

## 5. Получение данных и ограничения интеграций

- **Фаза 1:** проверенные ссылки на актуальные внешние карточки, ручная запись источника рейтинга и даты; собственные отзывы только с подтверждённого заказа; контент VK по разрешённым публичным ссылкам.
- **Фаза 2:** read-only интеграция через документированные и разрешённые API (если предоставляет платформа/есть права/тариф), очереди синхронизации; `last_sync_at`, provider errors, retry/backoff, freshness policy, source consent. Не обещать автоматический доступ к отзывам или личным сообщениям сторонних платформ без подтверждения технической возможности.
- **Фаза 3:** сводка тем обращений, time-to-first-response, CSAT, динамика оценки **по каждой платформе отдельно**; без манипуляций «создай отзыв за приз» и без обзвона/рассылок без оснований.
- Сохранять лишь допустимые данные; не парсить/перепубликовывать массово чужие отзывы и фото в обход условий площадок.
- Каналы соцсетей: VK `https://vk.ru/rakovar_yar` подтверждается публичным описанием; **MAX bot/channel, Telegram, Instagram и другие URL не подтверждены** — не придумывать их; в CMS предусмотреть переключатель `verified_owner` перед отображением и форму управления ссылками.

## 6. Критерии приёмки

1. По `/reviews` доступны карточки источников с раздельными рейтингами и точными ссылками, дата обновления, нет дублирования старого/нового объекта.
2. С мобильного устройства можно прочитать отзыв, перейти к источнику, отправить внутренний отзыв по своему завершённому заказу (после проверки авторизации), открыть чат поддержки.
3. Нельзя оставить отметку «подтверждённая покупка» без собственного завершённого заказа; клиент не может оставить отзыв от имени другого `customer_id`; запрещены XSS и утечки PII.
4. Негатив не пропадает из-за рейтинга, удаление/скрытие только с причиной, аудитом и возможностью проверки.
5. Без API или при timeout раздел остаётся читаемым и содержит корректные внешние ссылки; сомнительные цифры скрываются/маркируются `as_of`, нет ложного «обновлено сейчас».
6. Из редактора можно менять только разрешённые review/community blocks и привязанные источники, недоверенные HTML/iframe не исполняются.
7. В footer/header отражён подтверждённый VK; неподтверждённые MAX/Telegram аккаунты не публикуются.
8. Не используются чужие фотографии/тексты без прав и не происходит автоматического добавления отзывов из нескольких бизнес-карточек одной компании.

## 7. Зависимости задач

- `REP-01`: `WEB-01,WEB-02,CMS-01` — публичные страницы/блоки отзывов, рейтинги по источникам, ссылки и корректный mobile UX.
- `REP-02`: `ACC-01,ORD-01,ROLE-01,REP-01` — отзыв после завершённого заказа, безопасные ответы/обращения, административный workflow, consent.
- `REP-03`: `MKT-01,CMS-01,REP-01` — публикации VK и подтверждённых других каналов, интеграция только через разрешённый API, fallback.
- Для источников репутации обязательно сохранить `business_id`, дату и уровни проверенности; исключить карточки других городов.

**Только спецификация. Коммерческие права на данные, текущие дополнительные соцсети и точные статистические показатели в будущем требуют подтверждения.**
